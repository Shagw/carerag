# 🏥 CareRAG — Healthcare Policy Assistant

CareRAG is a **Retrieval-Augmented Generation (RAG)** assistant for healthcare and insurance
documents. Upload your policy, bill, or discharge summary, ask questions in plain English, and get
answers **grounded in your documents** — every answer shows the exact **source document and page**.

If the answer isn't in your documents, CareRAG honestly says **"I don't know"** instead of guessing.

> Built as a portfolio project on a **100% free** stack — no paid APIs, no paid hosting.

---

## ✨ Features

- 📄 **Upload PDFs** — policies, bills, discharge summaries, FAQs (multiple files, up to 10 MB each)
- 🔎 **Semantic search** — finds relevant text by *meaning*, not just keywords
- 💬 **Question answering** — natural-language answers generated by Google Gemini
- 📌 **Source citations** — every answer shows the document, page, and exact quoted snippet
- 🛡️ **"I don't know" guardrail** — refuses to answer when the documents don't cover it
- 🧠 **Conversation memory** — follow-up questions understand previous turns
- 🔐 **Per-session isolation** — each browser session only sees its own uploaded documents
- 🔁 **API key rotation** — rotates up to 5 Gemini keys with cooldown to survive free-tier limits

## 🧠 How it works (RAG in one picture)

```
UPLOAD (once per document)
  PDF ─► extract text + page numbers (PyMuPDF)
      ─► split into overlapping chunks
      ─► embed each chunk via Gemini embedding API (gemini-embedding-001, 768-dim)
      ─► store chunk + vector in Postgres (pgvector)

ASK (every question)
  question ─► embed via Gemini ─► find nearest chunks (pgvector cosine search)
          ─► strict "I don't know" guard (distance threshold)
          ─► build prompt (chunks + chat history) ─► Gemini writes the answer
          ─► attach citations (document + page + snippet)
```

See [`ARCHITECTURE.md`](ARCHITECTURE.md) for diagrams and module responsibilities, and
[`PLAN.md`](PLAN.md) for a beginner-friendly explanation of every concept.

## 🛠️ Tech stack (all free)

| Layer | Technology | Why |
|-------|-----------|-----|
| Backend API | **FastAPI** | Fast, typed, auto docs at `/docs` |
| Database | **Supabase Postgres + pgvector** | Free managed Postgres with vector search |
| PDF parsing | **PyMuPDF** | Extracts text **with page numbers** (enables citations) |
| Embeddings | **Google Gemini `gemini-embedding-001`** | Free-tier embedding API, 768-dim (server-side, so the app is lightweight) |
| Answer LLM | **Google Gemini (`gemini-flash-latest`)** | Free-tier API for answer generation |
| UI | **Streamlit** | Chat interface in pure Python |
| Deploy | **Streamlit Community Cloud** (UI) + **Render** (API) | Free hosting (see `DEPLOYMENT.md`) |

## 🚀 Run it locally

### 1. Prerequisites
- **Python 3.11+** (developed on 3.13)
- A free **Supabase** project (for the database) — see `DEPLOYMENT.md`
- A free **Gemini API key** from https://aistudio.google.com/app/apikey

### 2. Install
```bash
git clone <your-repo-url>
cd carerag

python3 -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements.txt
```

### 3. Configure secrets
```bash
cp .env.example .env
```
Then edit `.env` and fill in:
- `DATABASE_URL` — your Supabase connection string (use the **Session pooler** URI; remove any
  `?pgbouncer=true` at the end)
- `GEMINI_API_KEY_1` — your Gemini key (add up to 5 keys for rotation)
- `SIMILARITY_THRESHOLD` — leave at `0.8` (calibrated so real answers pass, off-topic is refused)

> `.env` holds your secrets and is git-ignored — never commit it.

### 4. Create the database tables (one time)
```bash
python -m app.database
```
Expected: `Tables created (or already existed). Database is ready.`

### 5. Start the app

Run the chat UI (one process — it calls the RAG logic directly, no separate API needed):
```bash
streamlit run ui/streamlit_direct.py
```
Open the Streamlit URL (usually http://localhost:8501). On first visit it asks your name to create
a private workspace, then you can create chats, upload PDFs into a chat, and ask questions.

**Optional — run the API too** (for the interactive `/docs`, or to use CareRAG as a service):
```bash
uvicorn app.main:app --reload   # then open http://localhost:8000/docs
```

## 🔌 API reference

| Method | Path | Purpose |
|--------|------|---------|
| GET | `/` | Health check |
| POST | `/upload` | Upload PDF(s) (form fields: `files`, `session_id`) |
| POST | `/ask` | Ask a question (`{question, session_id}`) → answer + citations |
| GET | `/documents?session_id=...` | List this session's documents |
| GET | `/history?session_id=...` | This session's chat history |

Interactive docs available at http://localhost:8000/docs when the backend is running.

## 🔐 Security note (please read)

This is a **no-login demo**. Documents are isolated **per browser session** using a `session_id`
kept in the page URL. This keeps different visitors' documents separate, but it is **not strong
security**: anyone who obtains a session's URL/id could access that session's documents. Do **not**
upload sensitive real medical records to the public demo. For production you would add real user
authentication.

## ⚠️ Known limitations

- **PDF text quality depends on the source file.** Text is extracted with PyMuPDF. Most text-based
  PDFs extract cleanly. However, some professionally-designed PDFs embed **decorative fonts with a
  broken character map** — where, e.g., the word "Treatment" is stored internally as `$u;-|l;m|`.
  That text is scrambled at the font level and **cannot be recovered without OCR** (which this
  project intentionally omits to stay lightweight and free). We strip obvious junk (control
  characters) and keep the readable text, so answers still work from the readable portions, but a
  few words/headings on such pages may appear garbled in citations. Using clean text-based PDFs
  gives the best results.
- **No OCR:** scanned/image-only PDFs (no embedded text) are rejected with a clear message.
